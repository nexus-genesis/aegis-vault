## 01 先认清现实：标准层已被巨头联盟闭环

修正版的事实前提：agent 支付的「协议默认层」不是空缺，而是 2025–2026 里被
Google、Visa、Mastercard、Circle 与多个联盟以「标准制定权」方式占住了。

| 协议 / 主体 | 定位于 | 状态 |
|---|---|---|
| x402 (Coinbase → Linux 基金会) | HTTP 402 机器原生支付执行层 | 2026-04 发布，基金托管 |
| AP2 (Google + 60+ 机构 → FIDO) | 标准化交易安全框架 / Mandate | 2026-04 捐给 FIDO 联盟 |
| ERC-8004 (以太坊) | Agent 链上身份 + 声誉 + 可验证授权 | 2026 已上线 |
| Visa / Mastercard | Know Your Agent、Agent Pay/Suite、Trusted Agent | 2026 live，Start Path 招 22 家 |
| Circle Agent Stack | agent 资金持有 + 程序化 USDC | 已发布 |
| APA 联盟 (Rain 牵头) | agent 授权/执行/保障规则 | 2026-08 成立，25+ 家 |

v0.1 的教训：上一版把这个库定位成「授权与问责默认层」、并把盈利希望押在
「被采用为标准」上——该位置已被上述联盟通过标准制定权占死。修正版明确放弃这条叙事。

## 02 重新定位：授权护栏即服务（Rails-as-a-Guardrail）

**一句话：Know-Your-Agent + 授权护栏，作为可被任意标准生态调用的应用层服务——
不是协议，是「让协议真正敢用」的落地层。**

应用层是巨头结构性留出的缺口：巨头「结构上无法快速构建的，恰是信任、合规、欺诈、
责任结算等让轨道可用的应用层」。而 Know-Your-Agent（KYA）——把软件主体绑定到
人类负责人、权限边界与不可篡改审计链——是被连续确认的真实细分，2025 约 $1.1B，
预计 2034 到 $27.8B，CAGR 55%。**口径折扣（2026-09-07 评审②）**：该数字是 KYA
身份验证整体盘子，Skyfire 等创业公司已在池内竞争，是直接对手而非背景板；本库能
触达的是其中「agent 支付护栏」切面，测算时按整体盘子的个位数百分比反推，不直接引用全盘 CAGR。
本库以「三级密钥绑定 + 接管 + 会话收窄 + 审计哈希链」为强项，天然落在 KYA 的应用层，而非协议层。

- ✗ **不做**：不再自称「第 N 套协议/标准」。不碰 x402/AP2/ERC-8004 已被锁定的身份与支付规则。
- ✓ **承接**：做把 agent 身份与权限「落地成可合规、可问责、可上保险」的护栏服务，绑定到既有标准。
- ✓ **兜底**：做巨头「看不上又做不快」的脏活累活：垂直映射、密钥救援、责任险数据、监管对接。

## 03 架构：护栏叠加在标准生态之上，而非自成生态

```
应用层 · 巨头违约金地
└─ 授权护栏即服务 · 本项目（aegis-vault）
     ├ KYA 身份绑定与权限边界
     ├ 授权护栏: 限额 / 会话收窄 / 接管
     ├ 问责: 审计哈希链 + 链上锚点
     └ 责任: 保单数据 / 密钥救援 / 合规映射
        ↓ 绑定 ↓ 锚点 ↓
巨头标准层 · 已锁定
  x402 / AP2 / ERC-8004 · Visa · Mastercard · Circle · APA
        ↓
agent 平台 · 钱包 · 企业金库 · 监管
```

**绑定标准，不重定义**：KYA 绑定结果可锚到 ERC-8004 验证注册表；授权快照可签入
AP2 Mandate；审计链可对接 APA 规则。作为「最后一公里」供应商，为 AP2/Circle 生态内
跑不动合规与责任的平台，提供可验证、可上保险的护栏服务。

## 04 价值主张：卖给被标准生态卡住的一侧

客户是「想接入 agent 支付、却背不动 KYA/合规/责任」的平台方——他们用标准，但不做落地。

| 客群 | 卡点 | 交付 | 付费锚点 |
|---|---|---|---|
| Agent 平台 / 框架 | 要接入 AP2/Circle 但缺 KYA 实现 | KYA + 授权护栏 SDK | 按受管 agent 数 / 护栏决策量 |
| 钱包 / 发行方 | 合规与责任缺失 | 审计链 + 责任数据 | 按受管账户数 + 审计报告份数 |
| 企业 / 金库 | 怕 agent 失控 | 链上硬上限 + 刹车（**EVM-first**，Solana 为软护栏） | 按账户数 + appliance 订阅 |
| 监管 / 审计 | 无法证明 agent 合规 | KYA 报告 + 链上锚点 | 合规/审计套餐 |
| 保险/再保 | 缺 agent 风险量化 | 可计算最大损失数据 | 数据 + 再保分成 |

关键洞察：巨头占标准，但标准本身不会自动变成「合规、可问责、可上保险」。
把「敢让 agent 花真钱」变成可交付服务——这才是应用层的货币化入口。

> ✅ 非托管条款（2026-09-06 评审①提出，2026-09-07 v0.2.1 已落实到全部定价口径）：
> **非托管授权护栏**——根密钥留在客户侧、Keeper 以 appliance 形态部署进客户边界，
> 我们卖策略执行 + 审计 + 责任数据，**不做资金托管，不按托管资产额计费**
> （避免落入 money transmission / VASP 监管域；本项目不构成 Money Services Business，
> 定价与营销物料统一使用上述口径，合同模板含同款声明）。

## 05 盈利模型：合规/落地/服务为主，不碰协议分成红海

核心原则：不与免费执行层和巨头标准拼价格，而是卖「落地与责任」。收入重心放在巨头不做的服务侧。

稳态收入结构：KYA + 授权护栏 SaaS 50% · 合规审计/责任套餐 25% · 责任数据(保险/再保) 15% · 标准落地分包 10%

| 支柱 | 模式 | 定价锚点 | 依赖前提 |
|---|---|---|---|
| KYA + 授权护栏 SaaS | 按受管 agent 数订阅 | 5–20 美元/agent·月（护栏决策量超量另计） | KYA 实现 + 审计闭环 |
| 合规审计 / 责任套餐 | KYA 报告、SOC2 映射、责任保单捆绑 | 一次性 + 年勘查费 | Phase 2 审计交付 |
| 责任数据(给保险/再保) | 可计算最大损失与授权快照订阅 | 数据订阅 + 再保分成 | 可量化 + 出险历史 |
| 标准落地分包 | 为 AP2/Circle 生态执行最后一公里合规/迁移 | 项目 + 维护费 | 生态采用本库 |

为什么不能主靠协议分成：标准层已被锁死且趋近零边际成本。护栏价值的定价基础是责任与合规，不是流水。
**所有支柱均按非托管口径计费**（受管 agent 数 / 账户数 / 决策量 / 报告份数），无任何「按托管资产额 bps」项——资产额计价只在客户代持资产时才成立，而本项目不做代持。

## 06 核心竞争力与反取代分析（2026-09-06 评审补充）

三层竞争力，护城河深度完全不同：

```
加密托管工程深度      → 门票，不是护城河（别人 1-2 年能追上）
标准生态卡位 + 中立性  → 分发优势（x402 中间件/AP2 联签/8004 锚定）
责任数据飞轮          → 唯一会复利的护城河
```

真正值钱的是第三层：谁手里积累最多的 agent 授权决策、限额触发、出险与最大损失分布
数据，谁就是 agent 保险的精算标准。中立性是反吸收的结构性资产——Visa 不会跑 Google
的护栏，Coinbase 不会用 Mastercard 的审计。

| 层 | 大厂能否吞掉 | 原因 |
|---|---|---|
| 托管型护栏 | 能 | Circle/交易所模式天然代持资产 |
| 非托管 appliance | 不能 | 大厂商业模式要握住托管关系 |
| Good-enough KYA | 部分吞掉 | 像 AWS IAM 之于 Vault，巨头给免费基础款 |
| 合规深度 + 保险数据 | 难 | 精算簿和历史出险数据买不来 |

真正要防的：① APA 联盟里冒出拿标准接口定义权的护栏初创（对策：抢做参考实现 + 数据
飞轮先转）；② 代码被 fork（对策：open-core 把 fork 变成分发，护城河放在数据和审计品牌）。

```
Stage 0（已完成 2026-09）  改名 aegis-vault + npm 8 包发布 + 诚实审计基线
Stage 1（0-3 月）   技术信誉：域分离 / 时限锁持久化 / 信封 AAD / 测试网真实结算
                    + x402 中间件原型
                    └ 门槛：外部开发者 1 天内跑通护栏 E2E
Stage 2（3-6 月）   1 个 design partner 上生产 + ERC-8004 锚定 + 进入 x402/APA 当执行方
                    └ 门槛：第一个外部真实限额部署 ← 全盘证伪点
Stage 3（6-12 月）  KYA 报告产品化 + daily ledger 风险数据接 1 家保司 + 3-5 个付费种子
                    └ 门槛：第一份数据合同 ← 护城河点火点
Stage 4（12-24 月） 数据飞轮：匿名风险基准 + 「aegis certified」认证计划 + 法人实体落地
Stage 5（24 月+）   类目标准 → 战略并购退出
```

**90 天可证伪里程碑（Stage 1）**：
1. 域分离：派生路径版本化 root→chain 域分离（NETWORK_SALT 不可变，legacy 路径保留，新增 v2）✅ 2026-09-06
2. PolicyTimelock 持久化 ✅ 2026-09-06（注：实现走 `aegis-agent-sdk` 的 store-interface——比"接 mcp-server SQLite"更通用，SQLite backend 实现该接口即可直插）
3. 信封下限 + AAD：KDF 参数地板 + keyId/agentId/chain 域绑进 AAD ✅ 2026-09-06
4. 真实结算 execute：remote-signer 链路挪到公共测试网跑真 relayer ⚠️ 脚本+runbook 就绪（`scripts/testnet-settle.mjs`），卡测试网资金——faucet 均需人类账号登录，待一个有 Sepolia 余额的私钥
5. 并行启动：谈 1 个 design partner——客户狩猎必须从 Stage 1 开始 🔄 公告 issue #1 + ERC-8004 上游贡献 thread（RI#21）已发，待首封署名外联
6. x402 护栏中间件原型：拦截支付授权 → 会话/限额校验 → 签名快照 ✅ 2026-09-06（并超额交付 AP2 联签包 + ERC-8004 锚定包）

**Stage 2 增补（2026-09-07 评审④）**：nexus-genesis.top 活体基建不关停，改造为
**KYA/护栏沙箱演示环境**——真实环境可跑通对 design partner 拉新是现成资产；
daily ledger 持久化（遗留待办）同时是保险支柱的 actuarial 数据源起点。
前置条件：解决 server 进程共用数据目录的写冲突（历史教训：多进程共写导致高度漂移）。

每个生态一个薄集成点，全部由同一个核心策略引擎驱动：

| 生态 | 集成点 | 交付物 |
|---|---|---|
| x402 | HTTP 402 支付中间件 | `aegis-guardrail-x402`：拦截支付授权 → 校验 → 签名快照 |
| AP2 | Mandate 联签 | 授权快照 → AP2 Mandate 序列化器（格式仍在迁移，做成可插拔） |
| ERC-8004 | 身份注册表锚定 | KYA 承诺哈希 + 审计链头写入 Identity/Validation Registry |
| Circle/托管 | 策略 webhook | 限额与 deny-list 策略端点 |

顺序：x402 → ERC-8004 → AP2。

**治理约束（诚实声明）**：Stage 1 100% agent 可执行；Stage 2 的联盟申请约 70%；
Stage 3 起需要人类法人主体签合同——纯 agent 治理结构下的硬依赖，需提前物色人类法人合作方。

## 08 规模测算

| 情景 | 时间窗 | ARR | 概率 | 条件 |
|---|---|---|---|---|
| 保守 | 1-2 年 | $0.3-1M | 高 | 数家 design partner |
| 基准 | 3-5 年 | $10-30M | 中 | 绑定 1-2 生态 + 数据合同点火（指数据订阅，非保单捆绑——保险销售周期 2 年起步，不进基准分子） |
| 激进 | 5-10 年 | $100-200M | 低 | 成为 KYA 类目标准 + 保险集成成熟（精算簿需 2 年+ 出险历史，见 Stage 3 门槛） |

自下而上交叉验证：100 万受管 agent × $10/agent/月 ≈ $1.2 亿 ARR + 数据/合规收入
（口径折扣后：该测算取自整体 KYA 盘子的乐观渗透，实际按个位数百分比切面反推更稳）。
退出形态大概率是战略并购（安全基础设施 10-15x ARR → $10-30 亿区间）：
卡组织（补 KYA）、CrowdStrike/Palo Alto（安全边界延伸）、Swiss Re/Munich Re（via 数据）、云厂商。

**母命题风险（必须诚实）**：这是对 agentic commerce 交易量本身的衍生押注。
如果 2027-28 年 agent 支付量没有起来，KYA 就还是 niche 市场。
每个季度都问方法论那句：先证伪——agent 真金白银的流量现在到底在哪？流量在哪，护栏就往哪搬。

## 09 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 标准层继续升级,吞噬应用层需求 | HIGH | 绑定生态而非对抗；若标准业务化则转型为执行方 |
| 根密钥 / 结算仍为演示级 | HIGH | Stage 1 优先补域分离 + 真实 execute + E2E |
| KYA 市场吸引大量合规创业进场 | MED | 用隔离签名 + 审计哈希链 + 责任数据差异化 |
| 品牌联想 / 独立项目未成立 | MED | 已完成 aegis-vault 独立命名（Stage 0） |
| 仅有「机会叙事」缺竞态验证 | 方法论 | 每次决策先证伪、先核「谁在定义规则」 |
| agentic commerce 交易量不及预期 | HIGH | 季度复核流量假设；护栏跟随流量走 |

## 10 结论与行动建议

前景成立的前提：不自建标准，而是做巨头标准生态之上被认证的 KYA 与授权护栏应用层。
盈利重心是合规/落地/责任服务，规模的关键是绑定生态并跑通责任闭环。

- **本月**：冻结技术地基（Stage 1 六项）——域分离 + KYA 实现 + 结算闭环 + x402 原型
- **2-3 月**：发布绑定 ERC-8004/AP2 的护栏参考实现；design partner 首个生产部署
- **半年**：独立品牌（✓ 已完成）+ 3-5 种子客户 + 责任保单捆绑首单

一句话收束：**这门生意的天花板是「agent 经济的审计与保险底座」——一个现在还不存在、
但被各方结构性需要、只有中立第三方能坐上去的位置。窗口期是标准联盟们
「协议先行、落地缺位」的 18 个月。**
